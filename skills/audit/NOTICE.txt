Written for this tool (not Cloudflare content):
    audit-mode.md         how `vapt audit` maps the audit skill's hunting stage onto the
                          tool's existing triage/verify stage
    validation-rules.md   the "Core validation rules" block from HUNTING.md, extracted
                          verbatim, plus a provenance header

Deliberately NOT vendored, because they describe a multi-agent harness this CLI does not
have: SKILL.md, HUNTING.md, RECONNAISSANCE.md, VALIDATION-AND-REPORTING.md, the
validate-*.cjs validators, and report-schema.json. Their orchestration model — isolated
hunters, coverage critics, per-run scratch dirs, an OS-enforced sandbox — is replaced
here by the tool's existing pipeline: audit produces candidates, triage adversarially
verifies each one, verify.ts cross-checks CVE claims.

The vendored files still mention `subagent_type:` and multi-agent vocabulary in places.
That text is harmless here but is not an instruction to this tool: `vapt audit` runs a
single agent and never delegates.
